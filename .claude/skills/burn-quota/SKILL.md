# burn-quota：重置前把額度換成有用的東西

目標不是燒 token，是在剩下的幾分鐘內交出看得到的成果。
這個 repo 是公開的，這份檔案和 `BACKLOG.md` 都不能出現個人資料或未修的資安細節。

## 0. 開始前（30 秒內完成，不要問問題）

1. 從使用者的訊息讀剩餘分鐘數。沒說就當 10 分鐘。
2. 每個 agent 的時限 = 剩餘分鐘數減 3，最少 3 分鐘。
3. 讀 `BACKLOG.md`，從「下一步」由上往下挑。
4. 跑 `nproc` 看核心數。

## 1. 怎麼派（重點）

- **直接用 Agent 工具，同一則訊息一次平行派出去。** 剩 10 分鐘派 15 到 20 個；剩 5 分鐘派 8 到 10 個。
- **不要用 Workflow 排隊。** Workflow 同時只跑 `min(16, 核心數 - 2)` 個；4 核的雲端容器只有 2 個，10 分鐘內跑不完。核心數 18 以上才考慮 Workflow。
- 共用規則先寫成一份 brief 檔放 scratchpad，每個 agent 的 prompt 只寫「先讀 brief」加上自己的任務，省下派工時間。
- 每個任務要小到一個 agent 在時限內做得完，並且自己驗證過才回報（bug 要重現或逐行追過；網路上的資料要實際打開頁面）。
- 沒有第二輪獨立驗證時，回報要明講可信度低一級。

## 2. 做什麼（兩條軌，各派一半）

### repo 軌：這個專案

照 `BACKLOG.md`。順序固定：

1. 上一輪找到但還沒獨立驗證的問題，先驗證。
2. 驗證過的 bug：修掉並補測試。
3. 測試缺口、文件和實際行為不一致的地方。
4. 都清完了，再做新一輪唯讀審查。

### 個人軌：使用者自己的事

- 來源是對話裡的使用者偏好（「我希望 Claude 幫我」那幾項），或本機的使用者層級 `CLAUDE.md`。
- 兩個都沒有：只跑 repo 軌，並在回報裡說一聲。
- 個人軌的任務內容、產出、進度**一律不寫進這個 repo**。

## 3. 每個 agent 都要遵守

- 對外服務唯讀：不寄信、不發文、不留言、不投履歷、不建帳號、不改使用者的雲端文件。
- 搜尋字串和對外請求不帶使用者的姓名、信箱、公司或產品名稱。
- 不編造。數字、規則、連結都要有來源，沒把握就標「未驗證」。
- 不真的呼叫 LINE、Google Sheets、LLM 等正式服務；要重現就用 mock。
- 動程式碼：只在指定的開發分支上改，開 draft PR，不 merge、不部署。
- 暫存檔放 scratchpad，不放 repo。

## 4. 重置之後

- **預設不再加派。** 已經出發的讓它跑完，不開第二輪。
- 使用者說要繼續，才用新額度。

## 5. 交件

回報用這個順序，短句、多分行：

1. 做完了什麼（附檔案路徑或 PR 連結）
2. 沒做完或沒驗證的
3. 「接下來可以：① … ② …」

然後更新進度：

- repo 軌：改 `BACKLOG.md`（做完的移到「已完成」，新發現的加到「下一步」），commit 並 push。
  - 未修的資安問題不寫細節，只寫「有 N 個資安項目待修，細節見對話」。
- 個人軌：
  - 本機：寫進 `~/.claude/burn-quota/personal-log.md`，產出放 `~/burn-quota-output/日期/`。
  - 雲端：沒有私人的持久空間。把產出檔直接交給使用者，並在回覆列出「做了什麼、下一步」。問一次要不要存進她的 Notion 或 Google Drive。

## 6. 在自己電腦上用

這個資料夾複製到使用者層級，所有專案都能用：

```bash
mkdir -p ~/.claude/skills && cp -r .claude/skills/burn-quota ~/.claude/skills/
```

本機沒有這個 repo 的 `BACKLOG.md` 時，repo 軌改成審查當下所在的專案。
